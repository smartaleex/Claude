# Alex HQ: how the code is laid out

One page to find your way around. If you are about to change something, read
"Where do I fix X?" first, then open the one file it names.

Alex HQ is a static progressive web app: plain ES modules, no build step, no
server, hosted free on GitHub Pages. Everything is stored on the phone.

## The ground rules

1. **One job per file, and files stay under about 300 lines.** The Training
   tool used to be one 1,700-line file; it is now 13 small ones. Keep it that
   way. When a file passes 300 lines, split it by job, not by size.
2. **Pure logic goes in `core/` and has a unit test.** Anything that decides
   something (what weight a set opens at, whether the comeback ramp is on,
   which cryptic clue is next) is a plain function with no DOM, so it can be
   tested in milliseconds. Screens only call it.
3. **A screen is a function that returns an HTML string**, and a `bind` that
   attaches handlers. Handlers are looked up by `data-act="name"` through
   `bindActions(root, { name(){...} })` in `core/ui.js`. There is no
   framework.
4. **Colours, fonts and radii come from tokens**, never hard-coded. See
   "Look and feel" below.
5. **Every new JS file must be added to `SHELL` in `sw.js`**, and `CACHE` in
   `sw.js` must be bumped on every deploy, or phones keep the old build.
   `npm test` fails if a file is missing from the list.

| File | Job |
|---|---|
| `state.js` | The saved store, screen state that is not saved, and derived facts (which phase, is the ramp on, sets per exercise) |
| `index.js` | Home-tile summary, mount, drawing a screen, wiring every module's `actions` |
| `plan.js` | Plan tab, the comeback banner, the legs note |
| `session.js` | A live session: exercise cards, start / finish / undo, rest timer sheet |

| `swap.js` | "Machine busy / using something else" |
| `goal.js` | Goal tab: weight trend, back-on-track plan, volume, focus |
| `history.js` | Past sessions |
| `photos.js` | Photos tab, before/after slider, goal photos |

| `physique-views.js` | How those readings are drawn |

Each module that responds to taps exports an `actions` map; `index.js` merges
them. To add a button: put `data-act="thing"` in the HTML and `thing(){}` in
that module's `actions`.

| Phone shows an old build | `sw.js` | bump `CACHE`; Settings has "Force update" |

## How state is saved

`core/store.js` exports `Slice`. Each tool makes one:

```js
const store = new Slice('forge', { ...defaults });
store.get();                       // the current object
store.update(s => { s.x = 1; });   // mutate, then it saves (debounced)
```

Saving flushes when the app goes to the background, so closing the app does
not lose the last tap. Photos are too big for localStorage and live in
IndexedDB (`core/photos.js`). Settings > Download a backup writes every slice
to one JSON file.

## Redrawing and scroll

Screens redraw by setting `innerHTML`. That used to throw the scroll position
away and leave the fixed tab bar and timer stranded halfway up the screen on
iPhone. Two rules fix it, and both live in `core/ui.js`:

- The page itself never scrolls. `#app` is a fixed full-screen scroller, so
  fixed elements cannot be left behind.
- Wrap any redraw in `holdScroll(() => { ...set innerHTML... })`. It holds
  the view height for a frame and restores the scroll position.

Weights are entered on a number pad drawn inside the sheet, so the phone's
keyboard never opens during a workout (keyboard open/close was the other
cause of the stranded bar).

## Look and feel

`tools/skins.py` is the single source of truth for four skins (Paper,
Instrument, Poster, Lichen), each in light and dark. It writes
`assets/css/skins.css` and fails if a text colour drops below WCAG AA
contrast. `app.css` only reads tokens. The skin is chosen with
`data-skin` and the theme with `data-theme` on `<html>`.

To change a colour: edit `tools/skins.py`, run `npm run skins`, commit both.

## Testing, lint, audit

```
npm install            once (dev tools only; the app itself has no dependencies)
npm test               everything: unit tests, then browser tests (a few minutes)
npm run test:unit      pure logic only (a few seconds)
node tests/run.mjs forge     only test files whose name contains "forge"
npm run lint           ESLint. "no-undef" catches a missing import before a phone does
npm run audit          dead exports, same-named helpers, files that have grown too big
```

Browser tests need Playwright's Chromium (preinstalled in the cloud
environment). They load the real app at phone size with seeded data and check
what is on screen, including that the tab bar stays pinned and the timer
does not float.

When you fix a bug, add a test that fails without the fix. The weight
carry-over bug is pinned by `tests/unit/sets.test.mjs` (the rule) and
`tests/browser/set-weights.test.mjs` (the screen).

## Deploying

Push to `claude/alex-hq-web-app-ndzk1l`. The workflow in `.github/workflows`
copies `index.html`, `manifest.webmanifest`, `sw.js` and `assets/` to the
`gh-pages` branch, which GitHub serves at
https://smartaleex.github.io/Claude/. Before pushing:

1. `npm run lint` and `npm test` are green.
2. `CACHE` in `sw.js` is bumped (`alexhq-v41` and so on).
3. Any new file is in `SHELL`.

On the phone, the app checks for a new build whenever it opens and reloads
itself once when one arrives. Settings > Build shows which cache is running.
